# Source reference

This is the file-level map of the current implementation. It accounts for
every file under `web/src` and the project entry/configuration files that shape
runtime, testing, and deployment.

Paths in the tables are relative to `web/src` unless stated otherwise.

## Engine

| File | Responsibilities and exports | Dependencies, callers, and invariants |
| --- | --- | --- |
| [`engine/body.ts`](../web/src/engine/body.ts) | Exports `Color`, imported numeric-limit constants, `PULLEY_RADIUS`, `normalizeAngle`, material presets, body palette, `BodyDict`, `Body`, `WallDict`, and `Wall`. Defines physical/visual properties, identity counters, inverse mass/inertia, kinetic energy, guarded serialization, bounded untrusted reconstruction, internal pulley-axle normalization, transient realised net force, and Performance sleep counters. | Imports guards and `Vec2`; used by every physical/render/edit subsystem. Anchors are body-shaped link endpoints but are locked, named consistently, and excluded from mutual gravity. Pulley axles additionally have fixed radius, no collisions/rotation/force/velocity, and cannot act as ordinary connector endpoints. Sleeping temporarily presents zero inverse mass but is never serialized. Realised net force is a completed-step diagnostic and is not serialized. Colour arrays are copied. Untrusted loads normalize angles; the explicit trusted snapshot path may preserve evolved finite angles exactly. |
| [`engine/links.ts`](../web/src/engine/links.ts) | Exports rod/spring/pulley JSON types, `DistanceLink`, `SpringLink`, `PulleyLink`, `Link`, and `linkFromDict`. Implements Hooke plus axial damping, one-sided elastic strings, ideal finite-wheel tangent geometry with equal-tension inextensible routing, link potential energy, transient axial-force display state, and guarded reconstruction. | Imports bodies, `Vec2`, and guards; used by world, renderer, interaction, inspector, presets, and performance solver. Links hold direct body references. Each pulley string owns one otherwise-uneditable third axle reference and retains wrap/mount topology while recomputing live tangent contacts; an axle cannot be shared or used by ordinary links/drivers on import. Distance/pulley warm-start state, spring axial reactions, effective spring coefficients, swept-stop samples, and tension-overlay choices are transient. Tension-only links must never push. |
| [`engine/contacts.ts`](../web/src/engine/contacts.ts) | Exports `RESTING_SPEED`, diagnostic `Contact`, `ContactStatic`, capsule helpers, kinematic clear/sweep functions, typed `ContactCacheEntry`/`ContactCache`, and `solveContacts`. Implements reusable size-aware spatial hashing, optional body-wall sweep, circle/capsule narrowphase, bounded/reused diagnostic contacts, impact propagation, warm-started impulses, friction/torque, split projection, and an O(contacts) fixed-support graph. | Imports only body/wall. Called by `World`; sweep helpers are also called by `CanvasController`. Normal pair keys remain stable across broadphase order. Maximum approximation omits key/cache/friction/support work while retaining bounce and separation. Position correction does not change velocity. Per-step static detection state cannot outlive structural edits. |
| [`engine/perf.ts`](../web/src/engine/perf.ts) | Exports performance caps/constants, `PerformanceLevel`, four-level substep/iteration/spring-pass tables, `performanceLevel`, `PerfSolver`, and `clampSpeeds`. Packs spring endpoints/rows, performs XPBD projection, publishes existing row reactions for diagnostics, applies bounded strain recovery, one final per-body displacement cap, velocity feedback, bounded damping, scatter, and global speed/spin caps. | Imports body and spring types; owned by `World`. This is the only alternate spring solver. No position write may bypass `PERF_MAX_MOVE_RADII`; recovery can span substeps. Diagnostic reactions reuse solved multipliers without another pass or per-row allocation. It remains stable for arbitrary inspector stiffness/damping/mass ratios and does not serialize its browser preference or scratch state. |
| [`engine/perf-gravity.ts`](../web/src/engine/perf-gravity.ts) | Exports `ApproximateGravity`, a reusable typed-array uniform-grid approximation with exact neighboring cells and aggregate distant cells. | Owned only by `World`; used for sufficiently large mutual-gravity scenes at Performance levels 1-3. It never runs in Normal mode and has no serialized state. |
| [`engine/world.ts`](../web/src/engine/world.ts) | Exports integrator names/type, scene collection limits and `SceneLimitError`, encounter constant, scene anchor/runaway helpers, field/driver types and classes, `WorldDict`, and `World`. Implements resource-bounded guarded reconstruction and duplicate-ID repair, reusable per-step/contact/force caches, exact packed and approximate grid N-body gravity, atomic two-axis field compilation, acceleration-level rod and pulley tension, three integrators including predictor-corrected velocity-dependent Verlet, encounter slicing, strict timestep validation, rod/pulley XPBD correction, swept zero-restitution pulley stops, paused taut axle editing, wall-mount synchronization, realised resultant diagnostics, Performance sleeping, bounded diagnostics, assembly-aware removal, and serialization. | Imports only core and engine modules. Used by app, scene, renderer, inspector, interaction type/value imports, and presets. The engine stays headless. `step` accepts positive finite time, treats zero/numerical underflow as an exact no-op, and throws on negative/non-finite input. Only short rigid `DistanceLink`s exclude endpoint collision. Pulley axles remain non-colliding globally; only their two owned particles receive the dedicated frame stop. Paused axle edits consume slack and then carry both particles without preloading the string. Object lists/properties are fixed within a step; reusable scratch avoids hot-loop allocation. Authored values, transient Performance levels and sleep state remain separate. Normal-mode force/energy models agree; approximate drift is explicitly marked. |

## Interaction

| File | Responsibilities and exports | Dependencies, callers, and invariants |
| --- | --- | --- |
| [`interact/tools.ts`](../web/src/interact/tools.ts) | Exports tool list/type, shortcut and help tables, and `CanvasController`. Implements picking, active-tool hints, pointer/touch/pinch routing, pan/unmodified-wheel zoom, body/wall/link/pulley creation, transactional position and continuously maintained velocity drags, live hysteretic pulley mount snapping, paused taut axle editing, wall endpoint edits, box selection, continuous transactional erasing, assembly-aware deletion reconciliation, duplication, interaction overlays, and their canvas/energy invalidations. | Imports core, engine, render helpers, touch predicate, and `App` as a type. Constructed/owned by `App`. Pulley placement and wheel dragging acquire a nearest-wall-end mount within 22 screen pixels; a live latch breaks beyond 34 screen pixels. Pulley strings pick on either straight leg, while the wheel owns its wrapped-arc hit area. Eraser segments sample at no more than three CSS pixels and commit one history entry per scrub. Modified wheel events are reserved for document-level suppression; custom touch gestures are scoped to the canvases. Pointer and parked-drag changes invalidate retained canvas pixels; direct position, velocity, and collection mutations also invalidate derived energy. Any world replacement resets direct interaction references and force-arrow hover. Position drag restores the grabbed velocity and applies a smooth speed-sensitive solver response: slow motion remains near one fifth of pointer speed while fast motion approaches 0.4 m/s. Rigid correction feedback uses the same pointer-derived rate, so rods receive one softened hand motion rather than a second substep-amplified impulse. Performance mode alone adds a linked chase cap. Velocity drag is the explicit throw/edit path and is reasserted after each live step while held. All deletion routes use the batched common path. |

## Important public interface index

These are internal module interfaces rather than a published npm API, but they
are the stable seams used throughout the repository:

- Model: `Vec2`, `Body`, `Wall`, `DistanceLink`, `SpringLink`, `PulleyLink`, `World`,
  `ForceField`, `Driver`.
- Serialization: `BodyDict`, `WallDict`, `RodDict`, `SpringDict`, `PulleyDict`, `FieldDict`,
  `DriverDict`, `WorldDict`, `snapshot`, untrusted `restore`, trusted
  `restoreSnapshot`, `SceneReadResult`, `SceneLimitError` and scene budgets.
- Simulation: `World.step`, typed `ContactCache`, `solveContacts`, `PerfSolver`,
  integrator names, imported numeric limits, diagnostics and removal helpers.
- App: `App`, `Settings`, `sanitizeSettings`, `Panel`, `GraphMode`.
- View/input: `Camera`, `ViewSettings`, `Selectable`, `Trail`,
  `CanvasController`, `Tool`.
- UI foundation: `Control`, `RefreshGroup`, `ModalFocus`, tab/splitter helpers,
  reusable control constructors, `TimeSeries`, timestamped `PhasePlot`,
  `handleShortcut`, and theme contrast helpers.
- Content: `Preset`, `PresetHints`, `PRESETS`, `CATEGORIES`, formula budgets,
  AST/parser/compiler and source/LaTeX converters.

Changing a field/type at one of these seams normally affects several modules,
tests, and at least one handbook page.
